# ACTP escrow verification

P1: when an authenticated oracle callback is the first dispute resolution while the kernel is DISPUTED, its principal award survives missing Tier1 winners and deferred mediator retries. Tier1 refunds never rewrite that award. This prevents a clean oracle win becoming a split.

P2: reserved platform-fee debt is unavailable as participant principal. Initial deposits equal participant and paid-mediator distributions plus actual fee outflow from the vault plus remaining vault funds. Entry and Tier1 bonds are separate. This prevents paying the same reserved money twice.

P3: FeeSplitVault's default profile is neutral to the protocol fee, refunds, mediator payouts and bonds: it differs from EscrowVault only by the integrator share taken from the provider's amount. Profile BOTH_AFTER_DISPUTE adds exactly the post-dispute refund fees (protocol at the locked rate, integrator at the smaller of its rate and the protocol's) and nothing else. Splits sum exactly, and no fee push can block a payout or a refund. This prevents a platform fee from changing what the protocol earns or what an undisputed party receives.

Use Python 3.10+, Linux bubblewrap, Forge 1.9.0, solc 0.8.34 and the installed shared Harness. No package installation, wallet, environment file or RPC is needed. Read each model result using the shared /statechart skill; it is the authority for the installed wrapper and reports shortest counterexamples. verify.py invokes that installed wrapper, without vendoring its implementation.

From repository root:

```sh

python3 .agents/skills/verify-actp-escrow/verify.py --out /tmp/actp-escrow-check --harness "$HARNESS_ROOT" --forge "$HOME/.local/share/actp-security-tools/bin/forge" --solc "$HOME/.local/share/actp-security-tools/bin/solc"
```

Set HARNESS_ROOT to your installed shared Harness root. Choose a new output directory on each run. Add --negative-controls to exercise disposable broken models, broken Solidity snapshots and a stale coverage hash. The full command is slower because each Solidity mutation recompiles. Ordinary verification runs the three models (FeeSplit under both profile configs) and eleven real-contract tests in three contracts, each with a stateful invariant suite (256 runs, depth 100, seed 0x9a117). Forge reports a contract's invariants as one test. The sandbox's process limit is set inside the sandbox with prlimit, so the number of processes the host user already runs does not matter. Deterministic companions assert observed callback success/deferral, exact late stale/sync rejection counts in both deferred/completed windows, and exact per-mode archive/collector/kernel flow counts for both escrows. Sticky handler failures are asserted outside actions so fail_on_revert=false cannot hide the tested mismatches. Known-valid callback, retry, duplicate and stale-first calls also record execution failures; duplicate refund rejection remains intentionally permitted. Marker order is first-writer, unexpected execution failure, per-row economic outcome, retry completion, callback completion. P1/P2/P3 counters are printed. Forge runs offline with no network, empty environment, read-only source and bounded writable build space. Outputs include exact logs and result.json with source hashes. Results are valid only if the entire command exits zero.

## Interpret results

Doctor exit 0 means synchronized; 2 means missing or malformed assets; 3 means source drift. A changed hash is NOT a broken property. A model counterexample is a bounded design failure; confirm its action mapping against real code before calling it a product defect. A real harness assertion is a concrete Solidity failure on the named seed/path. A compiler or tool error supplies no property result.

Negative controls are distinct: each model's mapped action is changed to violate its invariant; independent Solidity mutations reintroduce oracle-to-refund coupling or spending fee debt, and must fail both deterministic companions and their stateful invariant selections. Additional real-code controls force unexpected callback deferral, remove the stale guard, conditionally bypass the sync guard after completion, and make archive forwarding always revert. The first three must fail the named P1 stateful invariant and companion at the intended marker. Sync's canary preserves the deferred rejection so its recorded failure proves acceptance of a completed oracle result. Archive must fail the deterministic forwarding assertion; safe fallback need not violate conservation. Removing mediator retry must fail its completion check. Changing a covered source hash must report drift. Those are ten controls; the P3 controls below bring the total to 22, and the runner fails if it ran any other number. The stale mutation guarantees acceptance is challenged in the deferred window. Both APIs and both windows share the same late-result checker; conditional sync proves its completed-window acceptance handling. A separate completed-stale mutation is not included. The candidate is never mutated. Failure to see the intended invariant/assertion fails verification. After mutation checks, rerun the ordinary command cold against the unchanged candidate.

P3 controls: four model mutations and eight mutations of src/escrow/FeeSplitVault.sol, each required to fail at a named target. Model: the integrator share taken from the kernel fee must violate FeeNeutral; a refund fee without a dispute must violate RefundFeeOnlyAfterDispute; a disputed refund that charges nothing, and a protocol refund fee at half its rate, must each violate RefundFeesMatchRule (both satisfy conservation, which is why that rule is separate). Real code: a refund fee in profile PAYOUT_ONLY must fail invariant_DefaultProfileIdentical; ignoring the disputed flag must fail test_RefundFeeOnlyAfterDispute; a net basis, an integrator safeTransfer, a fee-recipient safeTransfer and a skipped refund split must each fail test_DeterministicSplitPathsAndCounters at the A3, blocked-integrator, blocked-fee-recipient and B-A9 assertions; a removed approval check must fail test_ConsentRejections; the refund side at the integrator's own rate must fail test_RefundSideCap. Before a mutation is applied the runner checks that its target was selected and run by the ordinary conformance pass. A control passes only when the log names the target as the failure with the expected marker; a compile error, a fixture failure or an unrelated revert fails the control.

## Bounds and assumptions

Both models contain two transactions. OracleRefund models an atomic callback plus attempted mediator call, independent pull refunds, optional Tier1 winner, retry, duplicate callback and timeout-first split. FeeDebt uses four abstract deposit units and a one-unit minimum fee, not all Solidity arithmetic. See model configs for finite constants. TLC safety exploration is exhaustive only within these abstractions; no fairness or eventual recovery is proved.

P1 excludes trusted admin/approved-resolver overrides. An override after a deferred callback can leave mediator retry pending and reverting: the real deterministic control records this accepted authority boundary. Timeout-first split followed by a late oracle no-op is a separate valid result, not an oracle-first guarantee. The two real P1 rows both cover the missing-winner/refund branch. Winner-present is abstracted in the model and exercised by separate BondEscalation suites; it is not covered by this stateful handler. Permissionless post-oracle stale and sync calls must reject and preserve the outcome. sync has no TLA action: its negative real-API calls check first-writer guard conformance. Pre-oracle trusted kernel resolution followed by permissionless sync is outside the oracle-first claim. Tier1 refund flooring may leave dust. The model does not claim all other refund or bounty arithmetic.

P3 uses one model, FeeSplit, under two configs (Profile Default and Both): two transactions, four deposit units, a one-unit kernel fee charged once, the integrator's provider-side share as one third of the provider's net amount, each refund fee as one quarter of the post-dispute refund, block flags for the integrator and the fee recipient, and a shadow plain vault stepped in lockstep. It does not model the bps arithmetic, the deposit clamp, the one-unit rounding bound, the paid mediator, the archive share, bonds, the kernel-view decoding or the void path. The real handler and test/FeeSplitVaultKernel.t.sol carry the exact arithmetic; test/FeeSplitVault.t.sol carries decoding and void, outside this runner. P3 assumes the candidate kernel (reserved fee debt, cumulative fee, at most one refund after a dispute), canonical token transfers apart from injected blocking, and no donations to the vault. The refund-side rule is exact for the single refund the kernel issues; arbitrary refund fragments are not reachable through the kernel and are bounded separately in the unit tests.

P2 assumes approved deployed vaults, canonical token transfer behavior (apart from injected fee-recipient blocking), and configured deployed archive treasury. Count vault-to-kernel fee transfer once, even if downstream archive forwarding fails. Kernel-held fee recovery is outside the two-vault model. External donations, malicious admin/vault/token/treasury, gas economics, all parameter values, upgrades, production RPC and chain integration are excluded. Real handlers exercise fresh fees on milestones and disputed exits, six terminal exits including paid mediator, four fee-recipient/archive availability combinations, successful archive forwarding, fallback/kernel retention, recovery, repeats and out-of-order actions. They are bounded randomized/deterministic evidence, not a proof for arbitrary Solidity executions.

CI runs doctor and these real harnesses through the regular suite. TLC is a developer gate requiring installed Harness; this change does not claim hosted TLC execution.
